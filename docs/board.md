# 隠し掲示板

URL: `/other/board/`

通常メニューからリンクしない、検索除外付きの掲示板。URLを知っている人は閲覧・投稿できる。アクセス制限や会員認証はない。PV集計からも除外する。

名前（任意・30文字）、本文（2000文字）を投稿でき、新しい順に30件ずつ表示する。自分の投稿は同じブラウザから削除できる。ブラウザの保存データを消すと削除できなくなる。

投稿先は「全体」または各ページを選択する。掲示板では全投稿の一覧と投稿先での絞り込みができ、各投稿には対象ページへのリンクを表示する。各ページの末尾には、そのページ宛ての最新10件を表示する。投稿操作は掲示板ページで行い、各ページから掲示板へのリンクは追加しない。

既存の投稿は「全体」に引き継ぐ。`/other/board/?page=weapons` のように有効なページIDを渡すと、投稿先・一覧の絞り込みを初期選択できる。

## 設定済みの掲示板を更新する場合

**今回のページ別投稿に対応するコードをデプロイする前に**、D1 `fefw-board` のConsoleで `sql/board-pages.sql` を一度だけ実行する。投稿先列と検索用インデックスを追加し、既存の本文・日時・削除情報は維持する。新規作成の場合は更新済みの `sql/board.sql` だけでよい。移行済みDBで `board-pages.sql` を再実行すると列重複エラーになる。

ページ追加・改名時は `node scripts/sync-board-pages.cjs` を実行する。掲示板自体と個別キャラ詳細を除くページから、投稿先の許可リスト、ブラウザ用選択肢、各ページの表示欄を同期する。キャラ関連の投稿先・表示欄は `/other/characters/` の一覧ページに統一する。

## Cloudflare Pages の設定

1. D1で掲示板専用の `fefw-board` を作成する。
2. `fefw-board` のConsoleで `sql/board.sql` を実行する。既存の閲覧数用 `fefw-stats` は変更しない。
3. Pagesの本番環境の設定 → バインディングで、D1バインド `BOARD_DB` を追加し、`fefw-board` を選ぶ。既存の `COUNTER_DB` → `fefw-stats` はそのまま残す。
4. Pagesの設定 → 変数とシークレットで、`BOARD_SECRET` を暗号学的な乱数32バイト以上の文字列にして、暗号化されたシークレットとして追加する。すでに設定済みならそのまま使える。ソースや公開ファイルには書かない。
5. 掲示板コードを含むコミットをプッシュし、デプロイ完了後 `/other/board/` から確認する。プレビュー環境は本番と別のDB・シークレットを使う。

掲示板は `BOARD_DB` のみを参照し、未設定時にも `COUNTER_DB` へ代替接続しない。旧手順で `fefw-stats` に掲示板テーブルを作成済みでも、削除は不要。そこに実投稿がある場合は、新DBへのデータ移行を先に行う。

設定不足時は「準備中」と表示し、ブラウザ保存だけの仮投稿には切り替えない。本実装だけでは本番D1へのテーブル追加やシークレット設定は行われない。

## ローカル確認

Node.js 22.13以降（`node:sqlite` 対応）で実行する。

```powershell
node scripts/preview-board.mjs 4173
node --test tests/board.test.mjs tests/page-counter.test.mjs tests/page-view-report.test.mjs
```

プレビューは `127.0.0.1` のみで待ち受け、公開対象を `dist` に限定する。APIは本番と同じハンドラーを使い、D1の代わりにローカルSQLiteを使う。閲覧数は `counter.sqlite`、掲示板は `board.sqlite` に分ける。ローカルDB・シークレットは既定でOSの一時ディレクトリ内 `fefw-board-preview` に保存し、HTTPで公開しない。第2引数でポート、第3引数で保存先を指定できる。

## 保存情報と制限

- 投稿の名前・本文・日時を公開する。
- 削除トークンはブラウザに保存し、DBにはハッシュだけを保存する。投稿一覧APIはこの情報を返さない。
- 同じ接続元からの投稿を30秒間隔に制限する。IPそのものはDBに保存せず、サーバーシークレットによるHMACを保存する。削除後も制限は残る。
- APIは本文サイズ、文字数、型、同一Originを検査する。SQLはバインドし、投稿はHTMLとして解釈しない。
- 通常の掲示板として広く公開する場合は、管理者削除・通報やTurnstileなどの対策を別途追加する。
- 管理者が緊急削除する場合はD1コンソールで対象IDを確認し、`DELETE FROM board_posts WHERE id = 対象ID;` を実行する。
