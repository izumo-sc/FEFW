# 掲示板

URL: `/other/board/`

掲示板設置ページのヘッダーから移動できる、検索除外付きの掲示板。URLを知っている人は閲覧・投稿できる。アクセス制限や会員認証はない。PV集計からも除外する。

名前（任意・30文字）、本文（2000文字）を投稿でき、新しい順に30件ずつ表示する。通常掲示板には削除ボタンを表示せず、通常APIも削除を受け付けない。管理者ページでは非表示・再表示のみ行い、完全削除はD1コンソールから行う。

投稿先は「全体」または各ページを選択する。掲示板では全投稿の一覧と投稿先での絞り込みができ、各投稿には対象ページへのリンクを表示する。各ページの末尾には、そのページ宛ての最新10件を表示する。投稿操作は掲示板ページで行い、各ページのヘッダーに、そのページを投稿先として選択した掲示板へのリンクを配置する。

既存の投稿は「全体」に引き継ぐ。`/other/board/?page=weapons` のように有効なページIDを渡すと、投稿先・一覧の絞り込みを初期選択できる。

## 禁止ワード

`lib/board-blocked-words.mjs` で候補を管理する。名前・本文をサーバーで検査し、該当時は400で拒否する。管理者投稿も同じ検査を通す。拒否した投稿は保存せず、連投制限にも加算しない。既存投稿は変更しない。

明確な罵倒・差別語・性的表現を選別し、短い語は独立した文字列のみ一致させる。全半角・英字大小・ひらがなとカタカナ・不可視文字を正規化し、長い禁止語では間の空白も吸収する。正規化は判定用のみで、保存本文を変更しない。句読点や改行をまたいだ結合はしない。単語リストによる検査なので文脈判定や全ての伏せ字・言い換えの検出はできない。誤判定があれば一覧を調整する。

## 管理者画面

URL: `/other/board/admin/`

パスワードでログインし、投稿の非表示・再表示と「管理者」バッジ付き投稿ができる。投稿先の選択・絞り込みは通常の掲示板と共通。管理者バッジは掲示板と各ページの最新10件に表示される。通常投稿では「管理者」を含む名前を拒否する。空白や不可視文字を挟んだ表記も判定する。本文での言及は許可する。通常メニュー・PV集計・投稿先には管理画面を追加しない。

既存の掲示板に追加する手順：

1. D1 `fefw-board` のConsoleで `sql/board-admin.sql` を一度だけ実行する。`board-pages.sql` がまだなら、先にそちらを実行する。既存投稿は通常投稿として維持される。新しいDBでは `sql/board.sql` のみを実行する。
2. Pages → 設定 → 変数とシークレットで、種類 **Secret**、名前 **`BOARD_ADMIN_PASSWORD`** を追加する。値は `BOARD_SECRET` と別の、暗号学的な乱数32バイト以上の文字列を使い、パスワード管理アプリなどに保存する。これは管理画面のログインに入力する値。既存の `BOARD_SECRET` は変更しない。
3. コードをデプロイし、上記URLでログインする。シークレットの追加・変更は次のデプロイで反映される。

ログインは8時間有効。セッションはHttpOnly・SameSite=Strict・Secure Cookieで保持し、DBにはトークンのハッシュだけを保存する。ログアウト時に削除し、管理者パスワード変更後のデプロイでも古いセッションは無効になる。失敗試行は接続元ごとに15分間で5回まで。管理者投稿も通常投稿と同じ30秒間隔制限を使う。管理者APIが未設定でも通常の掲示板は利用できる（DB移行は必要）。

## 非表示機能への移行

既存D1では、今回のコードのデプロイ前に `sql/board-hidden.sql` を一度だけ実行する。`is_hidden` 列を追加し、既存投稿は公開状態のまま保持する。新規DBは `sql/board.sql` のみでよい。ローカルDBは起動時に自動移行する。

通常APIは非表示投稿を一覧・ページング・各ページ表示に含めない。管理者APIは非表示投稿も返し、PATCHで状態だけを変更する。両APIとも投稿のDELETEは受け付けない。完全削除はD1コンソールで対象IDを確認して行う。

## 設定済みの掲示板を更新する場合

**今回のページ別投稿に対応するコードをデプロイする前に**、D1 `fefw-board` のConsoleで `sql/board-pages.sql` を一度だけ実行する。投稿先列と検索用インデックスを追加し、既存の本文・日時・削除情報は維持する。新規作成の場合は更新済みの `sql/board.sql` だけでよい。移行済みDBで `board-pages.sql` を再実行すると列重複エラーになる。

ページ追加・改名時は `node scripts/sync-board-pages.cjs` を実行する。掲示板自体と個別キャラ詳細を除くページから、投稿先の許可リスト、ブラウザ用選択肢、各ページの表示欄を同期する。キャラ関連の投稿先・表示欄は `/other/characters/` の一覧ページに統一する。

## Cloudflare Pages の設定

1. D1で掲示板専用の `fefw-board` を作成する。
2. `fefw-board` のConsoleで `sql/board.sql` を実行する。既存の閲覧数用 `fefw-stats` は変更しない。
3. Pagesの本番環境の設定 → バインディングで、D1バインド `BOARD_DB` を追加し、`fefw-board` を選ぶ。既存の `COUNTER_DB` → `fefw-stats` はそのまま残す。
4. Pagesの設定 → 変数とシークレットで、`BOARD_SECRET` を暗号学的な乱数32バイト以上の文字列にして、暗号化されたシークレットとして追加する。すでに設定済みならそのまま使える。ソースや公開ファイルには書かない。
5. 掲示板コードを含むコミットをプッシュし、デプロイ完了後 `/other/board/` から確認する。プレビュー環境は本番と別のDB・シークレットを使う。

掲示板は `BOARD_DB` のみを参照し、未設定時にも `COUNTER_DB` へ代替接続しない。旧手順で `fefw-stats` に掲示板テーブルを作成済みでも、削除は不要。そこに実投稿がある場合は、新DBへのデータ移行を先に行う。

設定不足時は「準備中」と表示し、ブラウザ保存だけの仮投稿には切り替えない。本実装だけでは本番D1へのテーブル追加やシークレット設定は行われない。

## ローカル確認

Node.js 22.13以降（`node:sqlite` 対応）で実行する。

```powershell
node scripts/preview-board.mjs 4173
node --test tests/board.test.mjs tests/board-admin.test.mjs tests/page-counter.test.mjs tests/page-view-report.test.mjs
```

プレビューは `127.0.0.1` のみで待ち受け、公開対象を `dist` に限定する。APIは本番と同じハンドラーを使い、D1の代わりにローカルSQLiteを使う。閲覧数は `counter.sqlite`、掲示板は `board.sqlite` に分ける。ローカルDB・シークレットは既定でOSの一時ディレクトリ内 `fefw-board-preview` に保存し、HTTPで公開しない。第2引数でポート、第3引数で保存先を指定できる。

管理者画面のローカル確認は、起動前に環境変数 `BOARD_ADMIN_PASSWORD` にローカル専用の32文字以上の値を設定する。本番用の値は使わない。ローカルDBは起動時に移行される。HTTPでのログインはlocalhost・127.0.0.1だけ許可し、その場合のみSecure属性を省く。環境変数を設定していない場合は管理者ログインを無効にする。

## 保存情報と制限

- 投稿の名前・本文・日時を公開する。
- 投稿トークンは従来の投稿形式との互換性のためブラウザに保存し、DBにはハッシュだけを保存する。削除権限には使用せず、投稿一覧APIもこの情報を返さない。
- 同じ接続元からの投稿を30秒間隔に制限する。IPそのものはDBに保存せず、サーバーシークレットによるHMACを保存する。削除後も制限は残る。
- APIは本文サイズ、文字数、型、同一Originを検査する。SQLはバインドし、投稿はHTMLとして解釈しない。
- 通常の掲示板として広く公開する場合は、通報やTurnstileなどの対策を別途追加する。
- 管理者が緊急削除する場合はD1コンソールで対象IDを確認し、`DELETE FROM board_posts WHERE id = 対象ID;` を実行する。

## 承認制

一般投稿は承認待ちで保存し、管理者画面の「承認」を確定すると公開する。管理者投稿は即時公開。一般APIの一覧・ページ別表示は承認済みかつ非表示でない投稿のみ返す。再表示操作だけでは未承認投稿は公開されない。

既存の本番D1では、コードのデプロイ前に `sql/board-approval.sql` を一度だけ実行する。既存投稿の公開・非表示状態は保持する。ローカルDBは起動時に自動移行する。

## 管理者返信

管理画面で各投稿の「管理者として返信」を開き、最大2000文字の返信を保存する。1投稿につき1つの返信を編集でき、「返信を非表示にする」で本文を残して非公開にできる。一般ユーザーには返信操作を提供しない。親投稿が承認済みかつ公開中の場合のみ返信を表示し、各ページの最新10件にも親投稿とセットで表示する。

既存の本番D1では、デプロイ前に `sql/board-reply.sql` を一度だけ実行する。新規DBは `sql/board.sql` に含まれる。ローカルDBはサーバー再起動時に自動移行する。
